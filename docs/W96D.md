# W96D BLE channel

W96D is intentionally isolated from the existing Xiaomi/MIoT control path. It has its own transport selection and BLE ownership rules; existing `/api/v1/fan`, `/api/v1/lamp`, Night Node MIoT discovery, recovery and morning handoff remain unchanged.

## Ownership

The app stores the environment explicitly:

- `HOME` → router owner, always.
- `SCHOOL` → router in `[06:00, 23:00)`, Xiaomi 10S Night Owner in `[23:00, 06:00)`.
- `OUTDOOR` → phone `BluetoothGatt` only.

No node probes another node to decide ownership. Router and Night Owner enforce their own half-open time window. `OUTDOOR` first asks the currently designated HTTP owner to persist a `release`; the phone then connects directly. On exit, the phone disconnects first and the app sends `resume` to the owner selected by the restored environment and current time.

If the designated node cannot be reached while entering `OUTDOOR`, the app does **not** silently fall back. It presents an explicit override that is only appropriate after the fan has physically left the old node's BLE range.

## Protocol used by this implementation

The implementation follows the supplied W96D V3.8 controller, including the extra services that are not visible in the simplified characteristic list:

- `FFF0`: main service
  - `FFF1`: power / physical gear command
  - `FFF3`: direct speed, one byte `0..100`
  - `FFF4`: natural wind
  - `FFF5`: BLE auto-shutdown delay (not battery telemetry)
  - `FFF6`: gear-down mode
  - `FFF7`: four physical gear calibration (read/leave unchanged by LanMiHome)
  - `FFF8`: Turbo duration
  - `FFFA`: indicator/light
  - `FFFB`: Turbo remaining seconds (not motor telemetry)
  - `FFFC`: Turbo enable
- `FFD0`: power telemetry service
  - `FFD1`: battery voltage/current/capacity
  - `FFD2`: VBUS voltage/current and charge state
  - `FFD3`: motor current/block state/voltage

Natural wind and Turbo are mutually exclusive. Direct speed follows the reference controller behavior: disable Turbo, ensure power on, disable natural wind, then write `FFF3`. The physical 4-gear calibration in `FFF7` is never changed.

## Unified API

Router sidecar and Android Night Owner both expose the same API on port `8766`:

- `GET /api/v1/w96d`
- `PATCH /api/v1/w96d`
  - fields: `power`, `speed`, `natural`, `turbo`, `indicator`
- `GET /api/v1/w96d/ownership`
- `POST /api/v1/w96d/ownership` with `{ "state": "release" }` or `{ "state": "resume" }`

`OUTDOOR` never calls these endpoints for control; it uses the same domain operations through Android `BluetoothGatt`.

## Router deployment

The W96D sidecar is separate from `router/lanmihome.py` and uses the already-required BlueZ/Bleak userspace stack.

```sh
sh /path/to/router/install-w96d.sh
vi /lotusemmc/lanmihome/w96d.json
/etc/init.d/lanmihome-w96d restart
```

For the home router set:

```json
"ownership": { "site": "home" }
```

For the school RAX3000M set:

```json
"ownership": {
  "site": "school",
  "day_start": "06:00",
  "night_start": "23:00"
}
```

If `device.address` is empty, discovery by a name containing `W96D` occurs **only while that router is the scheduled owner**. This is peripheral discovery, not owner election.

Quick checks:

```sh
wget -qO- http://127.0.0.1:8766/api/v1/w96d
echo '{"speed":42}' | curl -sS -X PATCH -H 'Content-Type: application/json' --data-binary @- http://127.0.0.1:8766/api/v1/w96d
echo '{"state":"release"}' | curl -sS -X POST -H 'Content-Type: application/json' --data-binary @- http://127.0.0.1:8766/api/v1/w96d/ownership
```

## Android setup

The client APK gets a `W96D` tab. The Night flavor additionally starts `W96dNightService`, which owns BLE only during `[23:00, 06:00)` and exposes the same API on `:8766`. Its service is independent of `NightNodeService`, so the existing 05:00–06:00 MIoT morning-handoff policy does not shorten the W96D ownership window.

On Android 12+ grant Nearby devices (scan/connect). On Android 11 and below, BLE scanning requires location permission. For the OnePlus client in `SCHOOL`, enter the 10S W96D API address once; the app will use that exact endpoint at night and will not probe other nodes.

## First hardware validation

Before changing any timing or reconnect policy, validate these in order:

1. Router: `GET /api/v1/w96d` connects and reports FFD1/FFD2/FFD3 telemetry.
2. Router: `PATCH {"speed": 42}` changes speed without changing FFF7 physical gear calibration.
3. Router: natural wind and Turbo toggle and exclude each other.
4. `release` disconnects router and remains paused across sidecar restart.
5. Phone `OUTDOOR` connects after router release and controls all five fields.
6. Exit `OUTDOOR`: phone disconnects before router `resume`.
7. School boundary: 10S disconnects at 06:00 and RAX3000M becomes eligible at 06:00; reverse at 23:00.
