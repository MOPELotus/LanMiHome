# W96D BLE channel

W96D is intentionally isolated from the existing Xiaomi/MIoT control path. The active design now assumes the router remains powered overnight, so the Xiaomi 10S Night Owner is parked rather than participating in BLE ownership.

## Active ownership

The app still stores the environment explicitly, but both fixed environments now use the router continuously:

- `HOME` → router owner, 24h.
- `SCHOOL` → router owner, 24h.
- `OUTDOOR` → phone `BluetoothGatt` only.

No node probes another node to decide ownership. `OUTDOOR` first asks the router sidecar to persist a `release`; the phone then connects directly. On exit, the phone disconnects first and the app sends `resume` to that same router owner.

If the router cannot be reached while entering `OUTDOOR`, the app does **not** silently take BLE ownership. It presents an explicit override that is only appropriate after the fan has physically left the router's BLE range.

The previous Xiaomi 10S implementation (`NightNode*`, `MorningHandoff`, `W96dNightService`) is retained in source/history but has no active UI, manifest entry, APK flavor, automatic start or ownership role.

## Protocol used by this implementation

The implementation follows the supplied W96D V3.8 controller:

- `FFF0`: main service
  - `FFF1`: power / physical gear command
  - `FFF3`: direct speed, one byte `0..100`
  - `FFF4`: natural wind
  - `FFF5`: BLE auto-shutdown delay
  - `FFF6`: gear-down mode
  - `FFF7`: four physical gear calibration (read/leave unchanged by LanMiHome)
  - `FFF8`: Turbo duration
  - `FFFA`: indicator/light
  - `FFFB`: Turbo remaining seconds
  - `FFFC`: Turbo enable
- `FFD0`: power telemetry service
  - `FFD1`: battery voltage/current/capacity
  - `FFD2`: VBUS voltage/current and charge state
  - `FFD3`: motor current/block state/voltage

Natural wind and Turbo are mutually exclusive. Direct speed follows the reference controller behavior: disable Turbo, ensure power on, disable natural wind, then write `FFF3`. The physical 4-gear calibration in `FFF7` is never changed.

## Router API

The router sidecar exposes the W96D API on port `8766`:

- `GET /api/v1/w96d`
- `PATCH /api/v1/w96d`
  - fields: `power`, `speed`, `natural`, `turbo`, `indicator`
- `GET /api/v1/w96d/ownership`
- `POST /api/v1/w96d/ownership` with `{ "state": "release" }` or `{ "state": "resume" }`

`OUTDOOR` never uses these endpoints for control; it performs the same domain operations directly through Android `BluetoothGatt` after the router has released BLE.

## Router deployment

The W96D sidecar is separate from `router/lanmihome.py` and uses the existing BlueZ/Bleak userspace stack.

```sh
sh /path/to/router/install-w96d.sh
vi /lotusemmc/lanmihome/w96d.json
/etc/init.d/lanmihome-w96d restart
```

Both home and school configs may simply identify the site:

```json
"ownership": { "site": "school" }
```

`site` is retained for configuration compatibility/documentation; active scheduling is continuous for both `home` and `school`. Old `day_start` / `night_start` fields are accepted but ignored.

If `device.address` is empty, discovery by a name containing `W96D` occurs while the sidecar is active. This is peripheral discovery, not owner election.

Quick checks:

```sh
wget -qO- http://127.0.0.1:8766/api/v1/w96d
echo '{"speed":42}' | curl -sS -X PATCH -H 'Content-Type: application/json' --data-binary @- http://127.0.0.1:8766/api/v1/w96d
echo '{"state":"release"}' | curl -sS -X POST -H 'Content-Type: application/json' --data-binary @- http://127.0.0.1:8766/api/v1/w96d/ownership
```

## Android setup

There is now one normal Android build. The `W96D` tab uses router HTTP in HOME/SCHOOL and native Android BLE only in OUTDOOR. The former Night flavor and Xiaomi 10S runtime entry points are parked.

On Android 12+ grant Nearby devices (scan/connect) when entering OUTDOOR. On Android 11 and below, BLE scanning requires location permission.

## First hardware validation

1. Router: `GET /api/v1/w96d` connects and reports FFD1/FFD2/FFD3 telemetry.
2. Router: `PATCH {"speed": 42}` changes speed without changing FFF7 physical gear calibration.
3. Router: natural wind and Turbo toggle and exclude each other.
4. Keep the school router sidecar connected across the former 23:00 boundary and confirm it remains owner.
5. `release` disconnects router and remains paused across sidecar restart.
6. Phone `OUTDOOR` connects after router release and controls all five fields.
7. Exit `OUTDOOR`: phone disconnects before router `resume`.
